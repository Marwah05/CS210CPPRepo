1. What value does topIndex hold immediately after construction, and why does that specific value make isEmpty() return the right answer with no special-casing?  
Immediately after construction, topIndex holds the value -1. That specific value makes isEmpty() simply check if the topIndex equals -1, and easily tell if it's empty without dealing with special-casing because it easily returns true if it's equal to -1.   
2. Walk through push step by step, in words: what happens to data and topIndex, in what order, and why would swapping that order break the stack?  
What happens is that it first checks isFull() to make sure if there's any room in the array. If the stack isn't full, the topIndex is increased by 1, and then that value is stored in data[topIndex]. Swapping the order could potentially store the value then increase the topIndex, which would place the value at the wrong position and cause topIndex to no longer represent the proper top number of the stack.  
3. Give the time complexity of push, pop, peek, isEmpty, isFull, and size, individually, in Big-O. For each one, justify it by describing what your code actually does, not by naming the general rule for stacks.  
push(): O(1) because it simply checks isFull(), increases the topIndex by 1, then store the value in the array. This doesn't require looping which makes it just big O of 1.  
pop(): O(1) because it does the same as push(), it checks isEmpty(), accesses the data[topIndex] then decreases the topIndex by 1, and finally returning its value.  
peek(): O(1) because it checks isEmpty() then returns which only takes one unit of time.  
isEmpty(): O(1) because it just compares topIndex to -1.  
isFull(): O(1) because it also just compares topIndex to 99.  
size(): O(1) because it calculates topIndex + 1 and nothing else.  
4. Exactly what happens in your code when push is called while the stack is full? State what prints (if anything), what gets returned (if anything), and whether topIndex changes. Then say why you chose that behavior.  
What happens is that isFull() returns the value true, which makes the code print "Stack is full, cannot push." It simply returns nothing but uses it to leave the function to avoid complications. Since push() is a void function, it doesn't actually have something to return. topIndex doesn't change because the stack is full, which just causes it to not add any new value to the data. I chose this specific behavior because it avoids exceptions (as it's an assignment requirement) and because it prints a message that tells the user nothing was added.
5. Exactly what happens when pop or peek is called while the stack is empty? Same level of detail as above.  
When pop() is called while the stack is empty, it makes isEmpty() return the value true. When that happens, the code easily prints "Stack is empty, cannot pop." and returns the value -1. The topIndex also doesn't change because the function returns before any access or changes can be made to the array.  
When peek() is called while the stack is empty, isEmpty() also returns the value true. This makes the code print "Stack is empty, cannot peek." and returns the value -1 as well. Same thing happens as pop(), topIndex doesn't change because the function exits before accessing or making any changes to data[topIndex]. I used -1 specifically as a sentinel value because the function can return an integer (int) that is negative because it clearly indicates that the operation cannot be done.
